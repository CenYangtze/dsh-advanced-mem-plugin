# 记忆

[English](design.md) | 中文

关于智能体所服务的这个人的跨会话记忆。[包索引](../README.zh.md#bundle-内容)列出八个插件；本页记录这个子系统为什么是现在这个形状。

## 问题

会话之间什么都不记得的智能体，会让同一个用户永远重复自己。最朴素的做法——把每份转录都追加进文件再贴回去——会因三个随使用而恶化的原因失败。原始转录无限增长，挤占请求空间。其中的一切看起来同样为真，于是一句随口的评论和一条长期指令分量相同。而且其中没有任何东西会变旧，于是用户上个月已经放弃的偏好，今天仍在为自己辩护。

一份可用的记忆必须做到转录做不到的三件事：把原始素材**压缩**为持久结论，按背后证据的多少给这些结论**排序**，并在证据不再到来时**让它们淡出**。它还必须始终诚实地区分这三者，因为一个以既定事实的确信度去执行陈旧猜测的智能体，比一个忘记了的智能体更糟。

## 形状：一个底层之上的两层结构

```text
                     ┌─────────────────────────────────────────────┐
   layer 1           │  nodes: person, preference, constraint,     │
   semantic graph    │         project, entity, routine,           │
   coarse-grained    │         tool-affinity, skill-affinity,      │
                     │         procedure                           │
                     │  edges: prefers, avoids, uses, works-on,    │
                     │         part-of, caused-by, co-occurs,      │
                     │         contradicts, supersedes             │
                     └───────────────────┬─────────────────────────┘
                                         │ evidence (every item cites records)
                     ┌───────────────────▼─────────────────────────┐
   layer 0           │  records: user-message, assistant-message,  │
   episodic substrate│           tool-invocation, skill-invocation,│
   fine-grained      │           procedure-step, artifact, note    │
                     │  each carrying terms, an optional vector,   │
                     │  provenance into the session log, and       │
                     │  attachment references to originals         │
                     └─────────────────────────────────────────────┘
```

**第 0 层保存素材。** 每一次值得留存的交互对应一条记录：用户自己的措辞、一次工具调用及其参数、一次被调用的技能、一件产物。文本会被建立词法索引；当挂载了嵌入器时，还会在采集时刻完成向量化。非文本原件——图像、视频 URL、文档——通过定位符、媒体类型、大小和摘要来引用。字节仍留在其所有者放置的位置；记忆从不重新编码原件，因为它自己做的副本，正是它可能出错的那份副本。

**第 1 层保存结论。** 节点是值得命名的持久主体：这个人是谁、偏好什么、持有哪些约束、在做哪些项目、习惯性使用哪些工具与技能、重复哪些例行流程。边是事件在主体之间诱导出的结论，每条都以模型可直接阅读的 `claim` 陈述。

**每个第 1 层条目都引用支撑它的第 0 层记录。** 正是这一条规则让图谱可审计：一个信念总能追溯到证据，证据总能追溯到某个会话与序号，用户问"你凭什么这么认为"时得到的是回答，而不是断言。

## 保真度

每条第 0 层记录都声明其文本对所发生之事的还原程度：

| 类别 | 含义 |
|---|---|
| `verbatim` | 原始措辞，可按记录的序号从会话日志重新导出。 |
| `summary` | 已知原件的有损压缩——例如一条在采集预算处被截断的提示。 |
| `derived` | 任何单一原件都未曾陈述的说法，例如渲染为可索引文本的一次工具调用。 |

这不是装饰。`MemoryQuery.minFidelity` 让消费方拒绝低于某个下限的一切，这正是未来的自动化界面得以基于 `verbatim` 素材行动、而把 `derived` 信念仅当作参考的机制。截断一条提示会把它降级为 `summary`，而不是保留一个它已不再配得上的 `verbatim` 声明。

## 作用域

记忆按覆盖范围分区：`session`、`workspace` 或 `user`。回忆读取一条作用域链，从最具体的一层开始，且从不自行扩大范围。

采集在会话有工作目录时写入 workspace，否则写入 user 作用域。session 作用域刻意从不作为默认值——一段随着习得它的那个会话一同死去的记忆永远无法被回忆起来，而这恰是让整个子系统失去意义的那一种结局。

## 写入路径

```text
session/event ──▶ memory-observer ──▶ ctx.memory.remember() ──▶ layer 0
     turn/end ──▶ memory-consolidation ──▶ ctx.memory.consolidate() ──▶ layer 1
                                       └─▶ ctx.memory.sweep()      ──▶ retirement + eviction
   tool call  ──▶ memory_write ────────▶ ctx.memory.assert()/relate() ──▶ layer 1
```

采集**读取日志**，而不是拦截循环。因此它观察到的正是被持久记录下来的内容，也无法改变模型所见——采集是这套框架的观察者，从不是其参与者。写入在单条链上串行化，且日志从不等待它：介质缓慢或失效只会削弱记忆，而不会拖住一个回合。

由插件、模型或工具产生的消息会被跳过。那些是框架在自言自语；采集它们等于把框架自己的输出当作关于用户的证据喂回图谱——包括循环地把回忆刚刚注入的那段记忆块也算进去。

### 证据不等于素材

只跳过框架产生的*消息*本身还不够，因为工具调用是被刻意采集的：一个人的智能体调用某个工具的频次，正是使用挖掘所消费的东西。但工具调用的文本是智能体自己的机器化输出，而本子系统的早期版本存下了原始参数 JSON，然后让回忆把它引述回去——于是一个会话会以"告诉模型它已经做过什么"开场，而且是整段 `run_code` 程序。

缺失的区分是**用途（use）**，一个与保真度并列的一等字段：

| 用途 | 种类 | 建索引 | 扩散激活 | 被引述回去 |
|---|---|---|---|---|
| `recallable` | `user-message`、`skill-invocation`、`artifact`、`note` | 是 | 是 | 是 |
| `evidence` | `tool-invocation`、`assistant-message`、`procedure-step` | 是 | 是 | **否** |

这个划分依据的是作者，而不是有用性。证据记录像其他记录一样参与排序与激活扩散——当查询命中背后的那些调用时，亲和度节点依然会被点亮——它们只是永远不会作为线索的文本被输出。`MemoryQuery.includeEvidence` 可以为审计界面解除这一限制；请求路径上没有任何东西会设置它。

在这个字段存在之前被采集的记录，会按其种类的默认值读回，因此既有存储在第一次读取时自行更正，而不需要迁移。

### 一次工具调用值得留下的是什么

只有人类用来给它命名的那一行。观察者取工具名，加上从它找到的第一个描述性参数（`description`、`query`、`pattern`、`command`、`file_path`……）中提取的短标签，以 `maxToolDigestLength` 为界，存下 `grep — find the config` 而不是参数对象。原始参数作为索引素材是有害的：任何提到某个路径的查询，都会命中一次恰好包含该路径的无关调用。

在 **Code Mode** 下，模型调用一个传输工具，并在程序内部驱动每一个真实工具，因此外层调用只说明"跑了一个程序"，挖掘它学到的是一个没人表达过的"偏好 `run_code`"。于是观察者在 `transportTools` 中点名传输工具，跳过它们自身的调用，转而采集 `tool/code-dispatch-start`——那才是说明哪些工具真正被调用的那些分发。

## 巩固：从行为到信念

巩固是"用户一直在做 X"变成"用户偏好 X"的地方。随包提供的蒸馏器完全不使用模型——频次、复现与相邻关系就是它推理的全部——这让它具有确定性、便宜到可以在每个回合边界运行，并且不可能产生幻觉。

- 被使用至少 `minObservations` 次的工具或技能，成为一个亲和度节点，携带其使用次数以及所跨越的会话数。
- 在单个回合内复现至少 `minSequenceRepeats` 次的动作序列，成为一个携带有序步骤的 `procedure` 节点。
- 每个被挖掘出的步骤得到一条通往其流程的 `part-of` 边，相邻步骤之间得到 `co-occurs` 边。

由频次得出的置信度是计数的饱和指数函数：一个行为的第二次观察比第二十次说明的问题多得多，而且任何计数都到不了上限，因为计数无法排除下一次交互恰好与之矛盾。

随包提供两个蒸馏器，两者都遵守上面那条规则：只有用户亲手写下的材料，才可以成为一条信念的*主语*。
行为周期挖掘器读的是重复——但只读技能的重复，因为技能是用户自己调用的；工具不是，工具是智能体代其调用的。
陈述式偏好挖掘器读的则是完全另一类证据：一个人直接说出自己想要什么。
两者合起来覆盖"你一直在这么做"和"你要求过这件事"，这是两种不同的断言，凭据也不同。

第二个之所以存在，是因为第一个看不见"请求"。频次挖掘只能学到某件事一直在发生，永远学不到某个人要求过它，
于是记忆系统能拿到的最直接的证据——"每次先跑测试"、"别用 npm"——就一直躺在情景层里没人读。
它的线索词表很小、双语、并且带锚点：约束类线索必须位于句首，因为祈使句的动词前面没有主语，
而这正是"不要强推共享分支"和"我从没收到过那封邮件"之间的全部差别。

蒸馏器是一道**能力缝**，而不是固定组件。可以同时挂载多个；中枢按 rank 顺序运行它们，并让每一份提案走同一条强化路径合并。一个抽取偏好*成因*的模型驱动蒸馏器，可以与频次挖掘器并肩接入，双方彼此无需知晓。

让这套机制成立的是合并而非追加。一个标签在其作用域与类型中已存在的提案节点会被强化：信念上升、证据增多、衰减时钟重置。这正是把一次重复行为变成一个自信信念、而不是一堆重复条目的原因。

## 读取路径

`ctx.memory.recall()` 运行三路独立信号，并以倒数排名融合：

1. **词法**——对已建索引词项做 Okapi BM25。分词器输出小写词段；对无空格书写的文字，还额外输出重叠的双字组，于是中文或日文查询无需分词词典也能命中它所嵌入的更长短语。
2. **向量**——与查询嵌入做余弦相似度，仅限于所存向量来自当前挂载嵌入器的记录。来自不同嵌入器的向量从不相互比较。
3. **图谱激活**——从直接命中的节点、以及被高排名记录所引用的节点向外扩散，沿活跃边传播若干跳，每跳带一个衰减系数。

倒数排名融合只消费位次，因此一个 BM25 分数与一个余弦相似度无需任何标定步骤即可结合——这也正是混合检索能够从容更换嵌入器的原因。

第三路信号是图谱换来的东西。只命中原始素材的查询依然会浮出由其得出的结论，命中一条偏好的查询会浮出该偏好所属的例行流程。每条返回的线索都携带把它排到该位置的信号，因此检索质量可被检视，而不是一个黑箱。

`ctx.memory.profile()` 回答的是无查询的那个问题：在什么都还没被问之前，有什么值得先说出来。它按经衰减的置信度、并以累积证据加权来排序活跃节点，于是一条证据充分的偏好排在一次自信的猜测之上。

## 信念生命周期

| 操作 | 效果 |
|---|---|
| 强化 | `c ← c + α(1 − c)`；支持度与衰减时钟前进。收益递减；永远到不了 1。 |
| 反驳 | `c ← c(1 − β)`；反驳计数前进。证据充分的信念能扛过一次分歧。 |
| 衰减（读取时） | `c ← c · 2^(−Δt / halfLife)`。半衰期为 `null` 则永不衰减。 |
| 撤回 | 立墓碑：退出回忆，仍可审计。 |
| 取代 | 旧节点标记为 superseded，并由一条 `supersedes` 边记录替代关系。 |
| 遗忘 | 抹除第 0 层记录，并删去对它的每一处引用。不可逆。 |

衰减在**读取时**施加，而不是由后台任务执行。这是这套设计安静的优势所在：陈旧性成为一个连续属性而非过期标志，一个不再被观察到的信念会自行淡出回忆，而一次强化就能让它恢复。维护扫描只为已经衰减到退休下限以下的条目立墓碑，因此漏掉一次扫描付出的是存储，而非正确性。

被断言的信念——用户明确说出的那些——不会衰减，也从不被扫描退休。是用户说的；只有用户能收回。

除了 `forget` 之外没有任何操作会就地删除，而 `forget` 存在的意义正是：要求删除素材的用户得到的是删除，而不是一份隐藏的副本。记录预算下的第 0 层驱逐会跳过任何被第 1 层条目引用的记录，因此抹除原始素材永远不会让某个结论失去依据。

## 主动记忆：协议

自动回忆回答的是记忆自己认为相关的东西。它回答不了智能体在任务中途才意识到的东西。因此工具包注册了一段固定提示词分节，点名四种值得主动检索的处境——选择方案、挑选工具或库、重复可能已经做过的工作、追问可能已被回答过的问题——并说明什么值得写入、什么不值得。

这段分节之所以存在，是因为这样宽泛的工具在没有它时会被稳定地忽略。它同时承载了整个设计所依赖的校准规则：被回忆起的记忆是**先验，而不是指令**。高置信度的记忆直接采用；低置信度的先核实；任何"做错了代价很难挽回"的动作，无论如何都先核实。

模型可以断言 `preference`、`constraint`、`project`、`entity`、`routine` 与 `person`。它不可以断言亲和度与流程——那些是从被观察到的行为中挖掘出来的，让模型写入它们等于让它自己的猜测伪装成使用证据。

## 面向人的那个界面

以上的一切都在跟模型说话。它们都回答不了用户真正的两个问题：*你以为你知道我什么*，以及*我怎么让你别这样*。`/memory` 是对二者的回答——它列出记忆的信念，每一行都带置信度与来源，统计有多少存储素材是仅作证据的，用与自动回忆相同的检索去搜索，并按其他视图打印出来的标签撤回某个信念。一个从某人身上学习的系统，必须让这个人不必绕经模型就能看见并删除它学到的东西。

`ctx.memory.suggest()` 是同一张图谱转向未来的样子：一个人反复回到的 `project`、`routine` 与 `procedure` 节点，按与常驻摘要相同的方式排序。偏好说的是*怎么*做而不是*做什么*，因此那些类型没有资格入选；当没有任何东西够格时，答案就是"没有"，而不是一份凑数的列表。这项导出住在中枢而不是某个界面里，因为排序与类型选择是记忆的判断——第二个界面（比如新对话页面上的一块面板）渲染同一个调用，而不是与它漂移。

## 组装

```text
ctx.storage ──▶ ctx.storage.domain ──▶ memory-store-domain ──┐
                                    memory-embedding-hash ───┼──▶ ctx.memory
                                                             │
      session/event ──▶ memory-observer ──────────────────────┤
          turn/end ──▶ memory-consolidation ──────────────────┤
    agent/pre-step ──▶ memory-recall ───────────────────────  ┤
         ctx.tools ◀── tool-memory ────────────────────────── ┘
```

完整栈由本包的 [bundle 层](../cordis.patch.yml)挂载，它期待一个已经叠加了 `@deepseek-ai/dsh-web-app` 的 profile——存储中枢与领域层就在那里。没有存储的组装依然能加载：`ctx.memory.ready` 为 false，采集与回忆静默跳过，工具在被使用时明确失败，而不是假装记得。

每一个可调项都是必填的 `Config` 字段——半衰期、阈值、预算、注入上限。一条偏好的合适半衰期取决于该部署怎么被使用，因此在这里给默认值是一个没有依据的选择，而不是一份便利。

## 开销

自动回忆由两个决定所限定。它按**回合**运行一次，而不是按步运行，因此一个漫长的工具调用回合只为它付一次费。而且它是一条追加在已认领输入之后的普通用户消息，因此只是延长请求前缀而非改写它，让系统提示词、工具 schema 与此前回合的服务端缓存复用保持完好。超出字符预算时按整行丢弃，而不是截断某一行——半条被记住的偏好是另一条偏好。

## 面向记忆辅助的自动化

这个子系统的下一批落地界面是那些真正作用于世界、而不只是谈论世界的界面：Computer Use、通过 MCP 接入的应用、办公文档、数据分析。这些在此都未实现。已经实现的，是那些界面将从记忆索取的东西，而每一件都各有其承重理由：

- **保真度类别与 `minFidelity`**——一个要编辑电子表格的自动化步骤，必须能够要求 `verbatim` 级的依据并拒绝基于 `derived` 信念行动。这个下限存在于查询接口上，因此这种拒绝是一道过滤器，而不是一条约定。
- **引用而非复制附件**——一段文档记忆指向那份文档。自动化界面解析当前原件，或者报告它已移动；它从不基于记忆自己做的陈旧副本工作。
- **`procedure` 节点**——重复的动作序列已经被挖掘为带有各自证据的有序步骤。这正是可重放例行流程所需要的形状，而从行为中挖掘它，才让"做那件我一直做的事"成为可回答的请求。
- **指向会话日志的溯源**——一次出错的自动化可以回溯到当初其记忆给出建议的那个确切回合。
- **以取代代替删除**——基于过时信念执行的自动化动作，在该信念被更正之后仍然可解释。
- **作用域分区**——在某个工作区学到的文档惯例，不会悄悄驱动另一个工作区里的动作。

真正缺失、且是刻意缺失的部分：没有应用适配器，没有动作执行，没有针对不可逆步骤的确认策略，也没有从动作的*结果*而非其发生来学习的蒸馏器。最后一项是最有意思的缺口——能力缝接受这样一个蒸馏器，但今天没有任何东西采集工具结果，因此也就没有可供学习的结果信号。

## 已知限制

各包自身的限制记录在各自的 README 中。子系统层面的限制是：

- **回忆按查询物化整条作用域链。** 所请求作用域中的每个活跃条目都会在进程内被读取并排序。`recordBudget` 为此设限；远超该预算的部署需要一个带真实索引的存储提供方，能力缝允许这样做，但随包提供的实现都没有。
- **一致性由调用方驱动。** 没有任何东西会察觉两个活跃节点彼此矛盾。`contradict` 与 `supersede` 必须由发现问题的一方调用。
- **没有结果信号。** 采集记录了某个工具被调用，从不记录它返回了什么。因此巩固学到的是习惯，而不是什么真正奏效。
- **没有脱敏。** 一条包含凭据的提示会像其他提示一样被采集；在提示中处理机密的部署需要在观察者之前加一道过滤器。
