# 1 项目概述与需求

**负责人：魏征。**

## 1.1 项目背景

国产操作系统正在把 Agent 放进桌面：它能理解任务、调用工具、执行文件与办公操作。但一次任务结束后，用户此前说过的事实、偏好和做过的方法，往往不能稳定地进入下一次任务。没有持久记忆支持时，Agent 每次都要重新询问路径、格式、工具和约束，跨会话连续性不足。

本项目面向这一缺口，为 OS Agent 增加可追溯、可管理、可复用的记忆层。系统不替换 Agent 内核，而是在 DeepSeek Harness（DSH）的会话与工具链路上接入记忆插件：事实通道保存“关于用户和工作区已经知道什么”，经验通道保存“这类任务怎样完成、需要哪些条件、怎样检查结果”。两条通道独立存储、独立召回、独立预算，避免把 Agent 的一次工具习惯误写成用户偏好。对应三项技术的固定叫法是：**多源分层记忆、证据约束的经验学习、任务感知检索与注入**；后文按这三条链路展开，不再另起名称。

项目要解决的问题包括：多源信息如何采集和留证；偏好与事实如何提取、更新和回溯；任务经验如何形成、验证和复用；端侧检索如何控制延迟；敏感信息如何过滤；自然语言遗忘如何落地；以及怎样用可复核的数据集和测试报告说明效果。效果数字与门槛统一放在第 7 章，本章只说明问题、目标和应用范围。

## 1.2 用户与任务

系统面向需要在国产 OS 上长期使用 Agent 的个人与团队。下列场景是应用范围，不等于三类场景都已完成同等深度的验收；已演示与待验证状态以第 7 章为准。

1. **个人助理 / 跨会话**：典型任务是为用户安排日程、整理材料、回答“上次说过的要求是什么”；需要保留的信息包括稳定偏好、称呼、格式要求、常用路径和明确约束；下次使用方式是在新会话中自动召回相关事实，并在回答中带上来源。
2. **办公自动化 / 文档整理**：典型任务是归档验收材料、批量重命名、按模板生成报告；需要保留的信息包括分类规则、命名规则、模板位置、不可删除项和检查方法；下次使用方式是按任务类型与环境匹配已有经验，先给出流程和验证方式，再执行。
3. **开发协作 / 项目迁移**：典型任务是在仓库迁移后补测试、改配置、复现构建；需要保留的信息包括新路径、旧备份约束、工具链版本和失败恢复方法；下次使用方式是在用户没有重复给出路径时召回项目事实，并在执行后把结果回流为新的经验证据。

## 1.3 七项需求对应

结合 XA-202612“OS Agent 记忆优化及高效应用研究”榜题，逐项说明系统怎样回应。本章只列需求、对应功能和当前状态；实现细节见第 2、3 章，指标门槛与实测结果见第 7 章。

1. **多源接入、清洗、标准化和质量校验**：对应 2.2 信息采集、3.1 采集与过滤、4.5 数据存储；当前状态为已有基础实现：用户消息、工具调用及结果、笔记和附件按来源记录，保留作者、会话、时间与证据引用，敏感信息在写入边界过滤。
2. **偏好提取、更新、跨场景使用和回溯**：对应 3.2 事实与偏好记忆、3.4 任务感知召回；当前状态为部分实现：显式偏好与约束可提取，改口有显式替换和受证据约束的语义替换；自由表达、复合偏好和隐含偏好的覆盖仍不足，当前口径未证明达到 85%。
3. **知识组织、冲突处理、流程与案例复用**：对应 3.2 冲突处理、3.3 经验形成与复用；当前状态为部分实现：L0 有规则改口，L1 有显式替换 API 和受证据约束的语义替换，经验按任务、环境、工具和验证结果组织；通用自动冲突判定与自然语言冲突的语义复核仍在进行。
4. **麒麟 embedding SDK、端侧部署和高效检索**：对应 4.4 SDK 实际启用、7.6 端侧性能；当前状态为代码与验证路径已有，默认配置未挂载 SDK，端侧词法检索已验收，SDK 实机长期稳定性与 30k/50k 单库规模待验证。
5. **敏感信息过滤和自然语言遗忘**：对应 3.1 敏感信息、3.5 遗忘；当前状态为部分实现：高置信凭据模式可脱敏或拒绝，显式 `forget` / `retract` 可用；用户自然语言“别记下来”尚未在采集前路由，目标行为未满足。
6. **与短期、中期记忆的数据交互**：对应 2.3 六步任务流、3.4 上下文预算；当前状态为部分实现：短期上下文由宿主会话提供，中期检查点与任务上下文由经验通道保存，长期事实与经验分域存储；三阶段流转的统一验收口径仍待补。
7. **标准化数据集评测和测试报告**：对应第 7 章；当前状态为持续进行：内部留出集上的偏好、召回、注入、性能、Agent 端到端和冲突实验已执行，部分结果完成 AI 逐例核对，冲突语义复核与官方盲测尚未完成。

# 2 系统架构

**负责人：张旭。**

## 2.1 DSH Agent运行内核

系统采用 DeepSeek Harness（简称 DSH）作为 Agent 运行内核，记忆模块以 Cordis bundle 插件形式接入。DSH 提供会话、模型调用、工具执行和权限管理等基础能力；记忆模块负责事实与经验的采集、保存、检索和注入；可视化控制台提供记忆查看与管理入口。

1. **DSH 的职责**：一次任务中，DSH 负责接收用户消息、维护会话与工具注册表、调用模型、执行工具、记录已提交事件，并在模型调用前运行 `agent/pre-step`  waterfall。记忆插件只在已提交事件之后读取，不拦截或改写 Agent 主循环。
2. **采用 DSH 的原因**：DSH 提供稳定的会话事件、模型服务、工具注册表和插件机制。记忆模块可以复用宿主的模型认证、存储域和权限边界，不需要另建一套 Agent 运行时；插件卸载或存储失败时，Agent 仍能继续执行，记忆退化为不可用而不是阻塞任务。
3. **项目实现的部分**：项目实现十个 Cordis 插件，包括事实记忆中枢、事实存储、观察器、蒸馏与召回、记忆工具与命令、经验引擎、经验存储、经验采集与评估、评测接口等；同时提供事实与经验两条注入链路、`/memory` 与 `/experience` 命令、记忆模型配置页和可移植 TypeScript API。

## 2.2 系统模块与职责

系统按“输入—记忆—检索—注入—Agent”划分模块。事实与经验分域存储，模块之间通过 DSH 服务与事件协作；部署位置统一在 4.5 说明。

1. **信息采集**：主要职责是读取已提交的会话事件、用户消息、显式 Skill 调用、工具调用及结果、笔记和附件，按来源记录作者、会话、时间、执行状态和采集完整性；上游是 DSH 会话日志，下游是事实蒸馏、经验采集和存储。
2. **事实记忆**：主要职责是保存 L0 原始记录、L1 语义节点与关系边，维护置信度、支持度、衰减、替代关系和证据引用；上游是信息采集与蒸馏器，下游是事实召回、`memory_search` 和控制台。
3. **经验记忆**：主要职责是把任务经历、可观察动作、结果与验证依据组织为 Episode 和 Skill，保存适用条件、前置条件、步骤、注意事项、验证方式、所需工具、环境约束和来源；上游是经验采集与结果评估，下游是经验召回、`experience_inspect` 和 `/experience`。
4. **检索与注入**：主要职责是按任务、作用域、环境和工具匹配候选，使用词法、向量和图激活融合排序，按字符预算逐行保留前缀后追加到模型输入；这是按物理行裁剪，不等于完整记录或完整 cue 不被截断。上游是事实与经验存储，下游是 DSH 的 `agent/pre-step` 和 Agent。
5. **管理或控制台**：主要职责是展示事实、偏好、经验、来源、状态和召回结果，提供搜索、查看来源、更新、撤回和遗忘入口；上游是记忆服务与存储，下游是用户和运维人员。控制台只读快照、演练副本与真实写回必须在界面上区分。

## 2.3 六步任务流

按“任务进入→记忆召回→上下文注入→工具执行→结果回流→记忆更新”说明一次任务怎样使用记忆。短期、中期上下文与长期记忆的交接随流程说明，不另设设计章。

1. **任务进入**：输入是用户消息、当前工作区、可用工具和会话历史；处理是 DSH 建立本轮请求、标记 `startsRequestSeries` 与步骤边界；输出是待处理的用户消息和任务上下文。
2. **记忆召回**：输入是查询文本、作用域链、当前环境、可用工具和记忆状态；处理是事实通道做词法/向量/图检索，经验通道做任务相关性、环境与工具匹配，统一经过 `rankScore` 和置信度调整；输出是候选事实、经验和来源计数。
3. **上下文注入**：输入是候选、`maxCues`、`maxCharacters`、`profileLimit` 和当前预算；处理是渲染事实区块、经验流程区块和来源摘要，`fit` 按换行逐行保留前缀，超出预算时在该行停止。这是物理行级裁剪，不保证完整记录：跨多行的单个 record 可能只注入部分内容，注入 ID 命中也不能等同于完整注入。输出是追加到 `decision.messages` 的 `memory-recall` 快照消息。
4. **工具执行**：输入是注入后的模型请求和工具注册表；处理是模型规划、调用工具、执行文件或办公操作，DSH 负责权限与审批；输出是工具结果、产物、执行状态和会话事件。
5. **结果回流**：输入是已提交的工具结果、最终检查或产物回读；处理是经验采集记录动作、结果和验证依据，独立评估器只在最后一次可能改变状态的操作之后引用完整检查或回读；输出是成功、失败、部分完成或未知的任务结果。
6. **记忆更新**：输入是已确认的事实、偏好、任务结果和经验候选；处理是事实蒸馏/替换、经验提炼与生命周期更新，保留证据、版本和替代关系；输出是新的 active 节点、Skill 或待确认状态，下一次任务重新走一遍召回与注入。

短期上下文是本轮会话消息与工具结果，由 DSH 直接维护；中期上下文是任务检查点、前驱请求和待完成任务，由经验通道按修订号保存；长期记忆是事实节点、关系边、Episode 和 Skill。三者的交接点是“已提交事件”和“检查点”：只有已经落盘的事件才能被采集，只有通过证据校验的结果才能进入经验。

## 2.4 DSH与控制台接口

列出记忆插件使用的 DSH 事件和服务，以及控制台读取记忆的接口，说明调用方和用途。

1. **宿主事件采集**：调用方是 `memory-observer` 与 `experience-harness`；用途是读取已提交的 `session/event`；说明是只读、串行写入，不拦截 Agent 循环，采集失败只降级记忆，不阻塞回合。
2. **记忆查询**：调用方是 `memory-recall`、`memory_search`、`/memory` 和控制台；用途是按作用域链检索事实、节点、边和来源；说明是查询文本在进入词法/向量前先经过安全过滤。
3. **上下文注入**：调用方是 `memory-recall` 与 `experience-harness` 的 `agent/pre-step`；用途是把事实区块、经验流程区块和来源摘要追加到模型输入；说明是每轮追加一次，保留稳定前缀，按字符预算逐行保留前缀；物理行不截半行，但跨多行的单个 record 可能只注入部分内容。
4. **结果回写**：调用方是 `memory_write`、显式替换 API、经验评估与反馈；用途是保存笔记、替换事实、确认任务结果、提炼 Skill；说明是写入必须带用户作者证据或可观察结果，工具输出和助手文本不能冒充用户偏好。
5. **控制台读取或管理**：调用方是本地 Web 控制台与 `/memory`、`/experience` 命令；用途是查看记忆、来源、状态、待确认任务和召回结果，执行搜索、撤回、遗忘和导出；说明是控制台通过宿主服务读取，不直接改存储文件；模拟操作与真实写回需在界面标注。

# 3 记忆机制

**负责人：张旭。**

本章按记忆形成和使用的顺序介绍机制，不单独列数据模型章。短期、中期上下文与长期记忆的流转随第 2 章任务流说明，本章不重复。

## 3.1 采集与过滤

介绍消息、工具调用及结果、笔记、附件等信息的采集入口、格式整理、字段校验和异常处理；敏感信息识别与过滤也在入口处说明，并写清实际处理位置。

1. **消息与助手输出**：采集用户消息、显式 Skill 调用和已提交的助手输出；用户消息可支持关于用户的知识，助手输出只作为 `evidence` 保存，参与排序和激活，但不作为可引述文本回到模型，也不用于偏好蒸馏。记录保留会话、回合、时间、作者和采集完整性。
2. **工具调用及结果**：采集工具名、动作、执行状态、结果摘要、检查和回读；原始参数、工具程序和隐藏推理不进入经验正文。并行修改、执行中断和内容截断保留“不完整”标记，避免把未完成操作当成成功证据。
3. **笔记与附件**：笔记按用户作者材料处理；附件只持久化声明过的字段，记录 URI、media type、digest、caption 等必要信息。附件引用命中敏感模式时整条省略并记为 `attachment-dropped`，原文件内容不改。
4. **敏感信息**：在 `remember`、`assert`、`relate`、`replace`、`memory_write` 和 `recall` 的统一运行时入口过滤。固定高置信模式覆盖 PEM 私钥、AWS/OpenAI/GitHub 风格 provider token、`Bearer` 值和明确的 password/api_key/secret/token 赋值；默认用固定 placeholder 遮蔽，也可配置为整段拒绝。该策略是最低限度、可解释的采集安全，不是完整 PII 分类系统；模式刻意收窄，既可能漏掉少见凭据，也可能误伤形似赋值的普通文本。

## 3.2 事实与偏好记忆

介绍事实记录、来源标记和关联方式，以及偏好从哪里提取、用户改变要求后怎样更新。新信息与已有信息矛盾时，说明判定依据、保留哪些证据，以及最终采用哪一条。

1. **新信息补充**：新事实先生成 L0 原始记录，再由蒸馏器生成 L1 节点或边。L1 必须引用 L0 证据；同一 label 的普通 `assert` 会原地更新 summary、confidence 和 evidence，不保留旧 L1 版本；需要保留旧值时使用显式替换。
2. **偏好改变**：用户明确改口时，L0 的 `linkCorrection` 规则会在旧记录上写 `supersededBy`，建立记录级链接；L1 通过 `replace` / `memory_write operation: replace` 创建新节点、写 `supersedes` 边并给旧节点墓碑。语义蒸馏器只有在模型明确输出 `replacement`、目标为同 scope 同类型 active 节点、主体/属性/适用范围匹配、目标与候选都是单值、且新证据 quote 存在于用户记录时，才应用替换；仅 value 不同不会触发替换。
3. **信息冲突**：冲突判定分层处理。L0 只处理以 correction 标记开头且至少包含两个主题词的窄规则改口；L1 的通用冲突判定没有全自动实现。显式替换要求用户作者证据和原文 quote；语义替换是模型基于引用文本的语义判断，不是“用户确实想替换”的代码证明，误判角色扮演、引文或第三方措辞的风险仍在。无法确认时保留旧值并把候选标为 `unconfirmed-replacement`，不自动退休旧数据。
4. **信息撤回**：`retract` 保留墓碑和审计历史，适用于“这条不再采用但仍需可查”；`forget` 用于用户要求删除的材料，删除源记录并传播到依赖它的经验，旧节点、替代边和反馈按依赖闭包处理。普通召回只返回 active 节点；被撤回、替代或遗忘的内容不会作为当前事实注入。

## 3.3 经验形成与复用

说明怎样从任务轨迹和结果中形成经验，记录哪些适用条件、执行步骤、验证方式和来源；后续任务怎样判断能否复用，以及复用后怎样记录结果。

1. **经验形成**：从已提交的任务轨迹中读取用户原始请求、可见工具结果、最后一段可见助手总结和最终验证；要求合并把跨轮请求整理为带版本的 `taskContext`，区分结果要求与用户明确指定的方法。只有工具工作完成、结果经过独立评估或用户确认后，才进入 Skill 提炼；纯规划轮保存检查点，不直接产生 Skill。
2. **保存与标注**：Skill 保存适用情境、前置条件、步骤、注意事项、验证方式、所需工具、环境约束、来源任务和结果依据。Skill 有 `candidate`、`active`、`expired`、`quarantined`、`deprecated`、`retracted` 等状态；版本变化产生修订记录，`supersedes` 连接替代关系，旧版本在新版本通过验证前保留。
3. **适用性判断**：召回时显式提供作用域、当前环境（操作系统、应用版本、浏览器类别、流程变体等）和可用工具；候选必须 active、未过期、满足全部环境约束，且所需工具在当前 Agent 工具注册表中可用。缺失的环境值不视为匹配；BM25、`rankScore` 和置信度共同决定排序。
4. **复用与记录**：自动注入只包含适用情境、前置条件、步骤、验证方式和精简来源计数；模型需要细节时调用 `experience_inspect` 展开 Skill、来源索引或验证原文。复用后，后续独立任务的实际动作和最终验证可以反馈到准确的 Skill 版本；仅被检索到或任务整体得分不足以建立归因，重复反馈按幂等处理，版本漂移会被拒绝。

## 3.4 任务感知召回与注入

说明任务内容、运行环境、可用工具、记忆状态和上下文预算怎样影响召回与注入。只介绍实际使用的检索方式；排序、融合和去重写到能够解释结果即可。

1. **任务内容**：查询文本决定词法候选和向量候选；事实通道对节点 label/summary、边 claim、记录 terms 做 BM25，经验通道对任务描述、步骤和适用情境做 BM25。任务中的对象、动作、格式要求和否定约束会影响候选范围与排序。
2. **运行环境与工具**：经验候选必须匹配当前环境和可用工具；事实通道按作用域链读取，最具体的作用域在前。环境标签描述影响执行的属性，而不是用户身份；同一 Skill 在不同环境可以保留不同版本。
3. **记忆状态**：只召回 active、未过期、置信度达到阈值的节点和 Skill；被替代、撤回、隔离或遗忘的内容不进入当前注入。事实通道还会按衰减和 `minConfidence` 过滤；经验通道直接检查有效期，不等待维护任务。
4. **上下文预算**：生产注入默认 `maxCues=8`、`maxCharacters=4000`、首回合 `profileLimit=10`、`minConfidence=0.2`。注入由 `fit` 按换行逐行保留前缀，超出预算时在该行停止；物理行不截半行，但跨多行的单个 record 可能只覆盖前几行，因此不能声称整条记录或完整 cue 不被截断。事实与经验使用独立字符预算，避免一条通道挤占另一条。首回合先注入画像，剩余预算再注入召回 cue；非首回合直接注入召回 cue。

## 3.5 遗忘

通过一个实际例子说明：用户提出遗忘要求后，系统怎样定位目标、确定删除范围、处理相关内容，并在删除后检查结果。

用户在控制台或命令中提出“忘记我的旧地址”后，系统先按 label 或节点 ID 定位目标，确认它属于当前作用域且状态为 active；随后区分两种操作：`retract` 只撤回当前结论，保留墓碑和审计历史；`forget` 删除源记录，并沿依赖闭包删除派生节点、替代边、后续确认、反馈和相关 Skill，最后以一个作用域快照提交。删除后重新查询该 label，确认普通召回不再返回旧值；经验通道还会在 `memory/before-forget` 等待清理，并使当前采集投影失效，防止回合结束时把已删除内容重新保存。

当前边界必须写清：显式 `forget` / `retract` 已存在，但用户自然语言“别记下来，也别在回答里主动提”尚未在采集前路由。开发场景 c4 中，这类原句仍被保存为可召回的 `user-message`，并在后续问答中被注入和答出。因此应表述为“显式遗忘实现存在，自然语言拒记的目标行为未满足”，不能声称自然语言遗忘已经完成。

## 4.3 必要配置

只列启动和验收必须修改的配置项，不展开完整配置全集。

1. **模型路由**：`modelSettings.mode` 取 `inherit`、`harness` 或 `api`；`inherit` 跟随当前会话，`harness` 指定其他 Harness 模型，`api` 使用 OpenAI 兼容地址、模型和凭据引用。含义是记忆辅助请求使用哪个模型；填写方式按实际提供商配置，不把密钥写入明文配置。
2. **采集安全**：`memory.safety` 必填，包含 `redactPrivateKeys`、`redactProviderTokens`、`redactBearerTokens`、`redactSecretAssignments`、`rejectSensitivePatterns` 和 `blockedLiterals`。含义是写入边界的高置信凭据处理；默认遮蔽，`rejectSensitivePatterns: true` 时整段拒绝。
3. **召回预算**：`memory-recall` 的 `maxCues`、`minConfidence`、`injectProfileOnFirstTurn`、`profileLimit`、`maxCharacters`。含义是每回合注入的 cue 数、置信度下限、首回合画像和字符预算；生产建议保持 `maxCues=8`、`maxCharacters=4000`，改动后必须重新测量注入长度和延迟。
4. **embedding 提供者**：在独立 profile 中配置 `memory-embedding`，字段包括 `enabled`、`runnerPath`、`model`、`modelVersion`、`dimensions`、`timeoutMs`、`maxOutputBytes` 和 `fallback`。含义是是否挂载麒麟 SDK、runner 路径、模型与维度、超时和降级策略；`fallback` 只允许 `lexical`，不静默换成特征哈希。
5. **存储与作用域**：`DSH_HOME` 默认 `~/.dsh`，事实存储使用 `memory` 域，经验存储使用独立的 `experience` 域；多租户部署使用独立 runtime 或命名空间前缀，不跨作用域合并。

## 4.4 麒麟 embedding SDK 实际启用

说明SDK的启用情况、接入方式、调用位置、返回结果和验证方法。

代码中提供 `embedding-kylin` 提供者：它不近似语义，而是为每段文本拉起原生 `memory_embed_runner`，runner 链接 `libkysdk-coreai-embedding`，经 `kylin-ai-runtime` / `kytensor` 调用 GTE Base，返回一行带 768 维向量的 JSON 状态。子进程边界把 SDK 崩溃、ABI 变化或运行时卡死挡在 DSH 进程之外；写入时先持久化原始记录再调用 SDK，SDK 失败不会丢掉用户原话；召回时查询 embedding 失败会退回词法，并返回固定的失败类别。

需要区分三件事：**代码存在**、**配置挂载**、**实机验收**。当前工作树的出厂 `cordis.patch.yml` 刻意不挂 `memory-embedding` 行，默认事实检索是词法排序和图激活；要启用 SDK，必须在独立 profile 中写全 `memory-embedding` 配置，并用 `KYLIN_EMBED_RUNNER` 或 `runnerPath` 指向实际二进制。验证顺序是：先运行 `memory_embed_runner "probe"`，确认 `status=pass`、`dim=768`；再确认 `dsh plugin --profile <name> --dump-config` 出现提供者；最后检查召回结果 `semantic=true`。只有至少一条可用库向量与可用查询向量完成排序，才算语义召回；仅挂载提供者、`semantic=false` 或退回词法，都不能写成“SDK 已验收”。

当前状态：SDK 接入代码、配置方式和验证方法已具备；默认配置未启用，端侧 SDK 的长期稳定性和正式 100 题未完成。短程 200 次调用与正式 100 题停止情况见 7.6，不在此重复数字。部署结论以最终提交版本和实机复测为准。

## 4.5 部署位置与数据存储

在本章完整说明各组件部署在哪里、数据保存在哪里、控制台怎样访问。其他章节不再重复部署位置。

1. **宿主或 OS Agent**：部署在目标麒麟桌面的本机 DSH 进程中；会话日志和运行日志位于 `DSH_HOME` 对应的会话与存储目录；说明是 Agent 主循环与工具执行在本机，模型推理可远程。
2. **记忆模块**：作为 DSH 的 Cordis 插件加载在本机进程内；事实数据写入 `memory` 存储域，经验数据写入独立的 `experience` 存储域；说明是插件不另开网络端口，存储失败时记忆降级、Agent 继续执行。
3. **控制台**：由 `dsh web` 在本机启动，默认 `http://127.0.0.1:3080`，通过启动器自动打开的带 token 地址访问；说明是控制台只通过宿主服务读取，不直接改存储文件；只读快照、演练副本和真实写回需在界面标注。
4. **麒麟 SDK 或模型服务**：`memory_embed_runner` 与 `kytensor` 部署在本机，模型文件由麒麟 AI 运行时管理；远程 LLM 或远程 embedding 按实际配置放在外部服务；说明是端侧记忆与检索不依赖外网，模型推理可能依赖网络。
5. **记忆存储**：事实记录、节点、边、经验快照和反馈保存在 `DSH_HOME` 下的宿主存储域；导出文件与原始会话日志遵循各自存储方的保留策略；说明是 `forget` 只管理记忆 API 所属存储，不自动删除外部导出或原始日志。

## 5.1 打开与快速开始

说明怎样打开系统、进入记忆界面，以及完成一次查看或查询的最短步骤。配实际界面截图。

1. 启动：在终端执行 `dsh web`，使用启动器自动打开的浏览器标签页；默认地址是 `http://127.0.0.1:3080`，不要手动去掉认证 token。
2. 选择模型：进入“设置 → 模型”，选择已配置的提供商和模型；需要单独的记忆模型时，在插件“记忆模型”页选择跟随当前会话、指定 Harness 模型或独立 API。
3. 进入工作区：打开一个工作区会话，先完成一轮普通对话，让采集器写入事实；回合结束后执行 `/memory` 查看条目。

## 5.2 查看事实与偏好

说明入口、筛选方式、条目内容和状态。配实际界面截图。

1. 入口：在会话中执行 `/memory` 查看当前作用域的事实条目；控制台打开后进入记忆列表页，选择事实或偏好分类。
2. 筛选：按关键词、状态（active、superseded、retracted）和作用域筛选；偏好与约束按 label、summary 和 attributes 展示，事实按来源和更新时间排序。
3. 条目内容：每条显示 label、summary、置信度、支持度、更新时间、状态和来源计数；展开后可以看到引用的 L0 记录、会话和回合。
4. 状态：active 表示当前采用；superseded 表示已被新版本替代；retracted 表示已撤回但保留审计；forgotten 表示已删除，不再出现在普通召回。控制台如为只读快照，会在页面标注“快照”，不把快照当成实时写回。

## 5.3 搜索记忆与查看来源

说明怎样输入查询、阅读命中结果、打开原始来源，以及查看某次任务使用了哪些记忆。

1. 输入查询：在 `/memory search` 后输入自然语言关键词或短句；查询会先经过安全过滤，再进入词法/向量检索。
2. 阅读命中：结果按融合分数排序，显示条目类型、摘要、置信度和来源计数；命中多条时优先看 active 且来源完整的条目。
3. 打开来源：选择条目后查看引用的 L0 记录、会话 ID、回合位置和时间；来源被删除或脱敏时，界面显示缺失或 placeholder，不还原被删原文。
4. 查看任务使用：在经验侧执行 `/experience sources <skill-id>` 查看来源索引；在事实侧查看某次召回注入的 `memory-recall` 快照，确认本轮使用了哪些事实与经验。

## 5.4 更新与遗忘

说明现有更新、撤回和遗忘操作的入口、步骤和结果，在相应步骤中标明模拟操作。

1. 更新事实：在对话中明确改口，或使用 `memory_write` 的 `operation: "replace"`，提供目标节点 ID、用户作者证据记录 ID 和原文 quote；系统创建新节点、写替代边并退休旧节点。控制台若提供“更新”按钮，先确认它写的是演练副本还是真实存储。
2. 撤回：执行 `/memory forget <label>` 撤回指定知识，保留墓碑和审计历史；适用于“不再采用但需要可查”的情况。
3. 删除：调用 `memory_forget` 并设置 `mode: "erase"`，删除源记录并传播到依赖它的经验；适用于用户明确要求删除材料的情况。
4. 结果检查：更新后重新执行 `/memory search`，确认旧值不再是 active；删除后确认普通召回不再返回旧值，并检查相关经验是否一并清理。
5. 模拟操作标注：控制台中的演练、预览、回滚和批量操作如只改副本，必须在按钮或结果页标注“演练副本/模拟”，不能写成生产写回；提交与回滚能力未核验时，只写“可演练”。

## 5.5 常见问题

1. **执行 `/memory` 没有条目**：现象是列表为空或只有少量记录；处理方法是确认插件已加载、当前工作区有已提交会话、模型可用、存储目录可写；首次对话后等待回合结束再查看。
2. **搜索没有结果但记得说过**：现象是关键词搜不到；处理方法是换用条目中的原词、检查作用域是否一致、确认记录未被撤回或遗忘；若来源被脱敏，按 placeholder 查找而不是原文。
3. **`semantic=false` 或召回很快但结果很浅**：现象是召回报告词法模式；处理方法是检查 `memory-embedding` 是否挂载、runner 路径与权限、`kytensor` 健康状态和维度是否为 768；SDK 不可用时系统按设计退回词法，不要把词法结果当成 SDK 结果。
4. **经验列表为空或一直待确认**：现象是任务结束但没有 active Skill；处理方法是执行 `/experience pending` 查看原因，确认是否有完整检查或产物回读；必要时执行 `/experience assess <episode-id>` 重审，或用 `/experience confirm <episode-id> success|failure|partial` 明确确认。
5. **遗忘后仍能看到旧内容**：现象是普通召回仍返回旧值；处理方法是确认使用的是 `forget` 而不是只 `retract`，检查作用域和存储是否一致，确认外部导出或原始会话日志不在记忆 API 管理范围内；自然语言“别记下来”当前不会自动阻止采集，需要显式遗忘。

2. **数据规模与测试条件**：检索实验为 470 题、每题独立 full-haystack，per-qid 396–616 records，单机、每题新建 store，ingest 为 per-qid 首次建库（cold-ish），retrieval/injection 在 ingest 后执行（warm-after-ingest）；未控制 OS page cache，不是严格进程全局 cold/warm。30k/50k 单库未测，per-qid 最大 616 turns 不能外推。

4. **资源使用情况**：SDK 短程测试记录 FD、线程和连接持续增长，CLOSEWAIT=0、EMFILE=0；这是资源泄漏风险信号，不能因为 200 次调用都成功就写成“稳定”。检索实验的资源使用未做完整采集，报告只给出时间分位数；后续需补 CPU、内存、磁盘和并发条件下的资源曲线。

## 7.7 结果分析

总结主要发现，结合任务例子解释表现较好和仍需改进的地方，列出后续优化方向。

主要发现有三点。第一，事实与经验两条通道的真实链路可以运行：DSH 事件采集、记忆存储、召回注入、Agent 回答和经验评估都能走通；偏好 B2 的 150 条 case/store 全部完成且可复核，召回两臂各 470 题完成、0 错误。第二，效果仍不够：偏好提取在 B2 上只有 case full 18/100、内容项 full 23/143，长对话、复合目标和隐含偏好大量漏；检索 R@10 75.07%、R@5 64.91%，没有达到 85%，A0/B1 也没有看到提升；冲突处理运行完整但语义复核未完成，不能写通过率。第三，端侧性能要分开说：retrieval 与 injection 两个组件在约 500 turns/qid 规模下 P95 远低于 500 ms，但合并口径、30k/50k 单库和完整 Agent 延迟未测；SDK 短程 200/200 成功但资源持续增长，formal 100 停止在 9/100，长期稳定性不能宣称通过。

表现较好的地方是来源可追溯和证据约束：L1 节点引用 L0 记录，经验 Skill 引用任务、动作和验证；显式替换要求用户作者证据和原文 quote，普通召回只返回 active 内容；敏感信息在写入边界过滤，显式遗忘可以传播到经验。仍需改进的地方是偏好提取的自由表达覆盖、冲突的通用语义判定、自然语言拒记、SDK 长期稳定性和大库规模。下一步优先做四件事：完成冲突 100+50 的真实语义复核并替换第 7.3 节待替换段；扩大偏好正例的隐含/复合覆盖并单独报告 direct/indirect；补 30k/50k 单库与合并口径延迟；修复 SDK 资源增长并用正式 100 题验证长期稳定性。

工程回归方面，本次干净候选在 Node `24.19.0` 上完成 `pnpm run check`：typecheck、22 个测试文件 410 项测试、build 和 bundle verify（10 个 patch row、16 个 entry point）通过，来源为 `code/dsh-advanced-mem-plugin/docs/delivery-20261107/verification.json`；Node `22.9.0` 的两个 bench 因 `node:sqlite` 加载失败，未计完整通过。历史 477 项测试和 68 项 SDK 集成检查属于更早工作树快照，与本候选分开；410 是剔除原 experience WIP 后的候选集，不是回归通过率下降。上述工程检查不建立偏好/冲突准确率、检索质量、大库延迟、SDK 长期稳定性或生产部署结论，最终以最终提交后的验证为准。

# 附录A 术语与缩略语

**整理：李锦。**

1. **OS Agent**：运行在操作系统桌面上、能够理解任务、调用工具并执行文件或办公操作的智能体；本项目为这类 Agent 增加记忆层。
2. **事实记忆**：关于用户和工作区“已经知道什么”的记忆，包含 L0 原始记录、L1 语义节点与关系边，结论必须引用原始证据。
3. **偏好记忆**：事实记忆中的一类，记录用户稳定的喜好、格式要求、工具选择和约束；与一次性指令、任务局部要求和助手建议区分。
4. **经验记忆**：关于“这类任务怎样完成、需要哪些条件、怎样检查结果”的记忆，由任务经历、结果评估和 Skill 组成，独立于事实图谱。
5. **L0/L1**：L0 是原始证据记录，定位到会话事件；L1 是由 L0 提炼的语义节点或关系边，必须引用 L0，支持追溯、修正和替代。
6. **embedding**：把文本映射为向量的表示；本项目在麒麟环境使用 GTE Base 768 维向量，默认配置未挂载时退回词法检索。
7. **召回**：根据查询、作用域、环境和工具，从事实与经验存储中选出候选的过程；本项目使用词法、向量和图激活融合排序。
8. **上下文注入**：把召回结果渲染为模型可读的事实区块或经验流程区块，按字符预算整行裁剪后追加到模型输入；不包含 Agent 生成。
9. **遗忘**：用户要求删除或不再采用某条记忆时的处理；`retract` 保留墓碑和审计历史，`forget` 删除源记录并传播到依赖内容。
10. **DSH（DeepSeek Harness）**：本系统采用的 Agent 运行内核，提供会话、模型调用、工具执行和插件接入能力；记忆模块以 Cordis bundle 插件形式接入。
